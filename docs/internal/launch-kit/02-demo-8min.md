# 8 分钟演示脚本

目标：让技术负责人相信三件事——**答案有证据、权限可审计、升级可回滚**；同时展示它不是只能跑 demo。

## 录制准备

- 全新 quickstart 栈，数据只保留 `examples/demo/` 两篇文档
- 浏览器 1440×900，系统深色主题，缩放 110%
- 终端字号 18px；预先执行过一次构建，录制时避免长时间编译
- 准备两个问题：一个可回答，一个证据不足；准备一条“引用回查”操作
- 关闭通知、书签栏与个人信息；租户名使用 `demo`

## 时间轴

### 0:00–0:40 开场（真人或字幕）

> “企业知识库不缺一个能回答问题的 Demo，缺的是能解释答案、能管住权限、还能安全升级的系统。
> 这是 RAG Platform：答案必须带证据，权限和升级都能被审计。接下来 8 分钟，我用一条命令跑通完整链路。”

屏幕：仓库首页 + 架构图，快速划过 Release 资产（SBOM、签名、平台二进制）。

### 0:40–1:30 一条命令启动

终端：

```bash
git clone https://github.com/hzc19970630/rag-platform.git
cd rag-platform && cp .env.example .env && ./scripts/quickstart.sh
```

旁白：

> “本地确定性模型，不需要模型 API Key；脚本会完成迁移、种子、索引和健康检查。
> 首次构建通常 10–20 分钟，这里加速播放。”

画面停在 Web 与 API 健康检查通过的输出。

### 1:30–2:40 建库：预置包不是模板

操作：
1. 打开 <http://localhost:5173>，开发登录点 **Continue**
2. **新建知识库**，名称 `demo-policy`
3. 预置包选择 `general-enterprise@1.0.0`
4. 指一下说明卡：默认 `top_k`、切块大小/重叠、格式范围

旁白：

> “预置包是数据件，不是引擎分支。建库时把默认值复制到知识库，后续包升级不会静默改变已有库；
> 租户可以克隆内置包再编辑，内置包保持只读。”

### 2:40–4:00 入库与证据状态

操作：
1. 进入知识库，上传 `examples/demo/retrieval-handbook.md` 与 `examples/demo/product-faq.md`
2. 等待状态 `EVIDENCE_READY`
3. 打开文档详情，展示版本与 Chunk

旁白：

> “解析、切分、Embedding、索引全部异步；每步有状态、幂等键与重试。
> `EVIDENCE_READY` 表示证据可以被问答使用，而不是‘文件上传成功’。”

### 4:00–5:20 问答与引用

操作：
1. 点 **问答**，创建会话
2. 提问：`How does hybrid recall combine keyword and vector results?`
3. 流式输出完成后，点开引用角标

旁白：

> “BM25 与向量并行召回后 RRF 融合；答案里的每个引用都必须指向本次授权证据。
> 引用可以回查到 Chunk 与文档版本，越权或未注册的引用会被拒绝输出。”

### 5:20–6:10 证据不足会拒答

操作：同一会话提问 `What is our 2027 revenue target?`

旁白：

> “没有证据时不会编造。拒答是产品行为，也是评测里的硬门禁。”

若本地模型返回了带引用的回答，改用 `product-faq.md` 之外的问题并重录；不要剪辑成“看起来拒答”。

### 6:10–6:50 反馈进入质量视图

操作：
1. 对第一条回答点 **有帮助**，再点引用
2. 打开 `/ops` → **检索质量**，指出有帮助率、引用点击、最近评估与回归状态

旁白：

> “线上反馈、引用点击和评估报告汇入同一视图；高风险检索变更保存前必须有 7 天内的评估，
> 指标下降超过阈值会触发告警。”

### 6:50–7:30 租户自定义包

操作：
1. 打开 `/admin` → **预置包**
2. 克隆 `general-enterprise` 为 `demo-pack@1.0.0`
3. 编辑 JSON 把 `top_k` 从 8 改成 5，保存并查看

旁白：

> “内置包不可改；租户克隆后可以编辑自己的版本。
> 用新包建库，默认值来自这个租户包，而不是全局配置。”

### 7:30–8:00 升级与收尾

画面（可选）：终端快速展示升级演练摘要

```text
Upgrade drill passed: v0.1.0 -> <commit>
42 assertions, backfill 32 -> 0, image-only rollback
```

旁白：

> “v0.1.0 到 v0.2.0 做过真实双镜像演练：迁移、回填两次、检索与 SSE、预置包与质量接口，
> 最后只切回旧镜像完成回滚。代码、文档和 Release 都在 GitHub，链接在简介。”

结尾字幕：仓库地址、文档站、Release 页、“暂不支持 OCR/HA/多连接器”。

## 故障备选

| 情况 | 备选 |
| --- | --- |
| 首次构建太慢 | 提前构建；录制时展示已启动栈；终端片段单独补录 |
| 上传解析慢 | 预先上传好文档，从列表开始；或 2× 加速并保留状态切换 |
| 本地模型回答太短 | 用 `retrieval-handbook.md` 中的原句提问；不要改成模型无法回答的问题 |
| 拒答未触发 | 换一个 demo 语料完全未覆盖的问题（如预算/路线图日期） |
| 引用点击无响应 | 检查引用是否已被删除；重录该镜头，不要用假截图 |
