## 文章 1：答案可审计——RAG 的引用校验、越权拦截与拒答

**目标读者**：正在把 RAG 推进到生产、被安全/审计质疑的技术负责人。

**标题备选**
- 《RAG 的答案为什么必须能被审计：一次引用校验的工程拆解》
- 《别只展示引用角标：把证据链做进答案路径》

**开篇钩子（150 字内）**
> 大多数 RAG Demo 都能在回答下面放几个链接。但审计要问的是：这个引用是不是本次授权证据？
> 文档被撤权后旧答案还能不能回查？没有证据时模型会不会编？这三个问题决定 RAG 能不能进生产。

**结构**
1. 问题：引用“看起来有”与“可验证”的差距
2. 证据集与授权范围：检索前先算 scope，引用必须来自 evidence set
3. 引用注册与校验：答案输出前的 validation；失败时拒绝输出而不是静默降级
4. 越权与撤权：权限负向用例、ACL version、删除/恢复后的行为
5. 拒答：什么算“证据不足”，为什么拒答要进评测门禁
6. 可复现：指向 `scripts/m3_acceptance.sh` 的权限负向与拒答断言、`docs/evaluation.md`
7. 边界：不是“零幻觉”；引用只能证明“答案基于这些证据”，不能证明证据本身正确

**证据链接**
- [架构说明](../../architecture.md)
- [评测说明](../../evaluation.md)
- `scripts/m3_acceptance.sh`（引用、拒答、越权断言）
- `docs/comparison.md` 的“Answer provenance”行

**CTA**：一条命令跑通 quickstart，问一个语料外问题观察拒答。

## 文章 2：一次可回滚的向量空间迁移——从 `chunks.embedding` 到变体表

**目标读者**：准备换 Embedding 模型/维度、又不敢停机重建的团队。

**标题备选**
- 《换 Embedding 模型一定要重建全库吗？一次可回滚迁移的工程记录》
- 《从 0.1 到 0.2：把向量迁移做成状态机，而不是一次性脚本》

**开篇钩子**
> 换模型最危险的不是重算慢，而是“算到一半、旧索引已不可用、还回不去”。
> 我们把迁移拆成可观察的状态机和可回滚的镜像切换，并用 v0.1.0 → v0.2.0 的真实演练验证。

**结构**
1. 旧方案的问题：单列向量 + 单一维度，切模型只能全量重建
2. 设计：`chunk_embeddings(chunk, model, dimension)` 变体表；旧列保留并双写
3. 迁移状态机：pending → building_index → reembedding → verifying → ready → cutover → finalized/rolled_back
4. 升级顺序：`migrate → backfill → docreader → worker → api`；回填幂等（第二次 inserted=0）
5. 回滚边界：只切镜像；`finalize` 清理旧空间后只能恢复备份
6. 数据面：1M 行 p95 98.5ms（注明测试条件与报告位置）
7. 不支持什么：跨库联邦、自动 finalize、无备份回滚

**证据链接**
- `migrations/postgres/0031_embedding_variants.sql`
- `internal/embeddingmigration/service.go`
- `scripts/d3_acceptance.sh`
- `scripts/upgrade_drill.sh`（42 项断言，报告不入库）
- [发布手册](../../releases.md) 第 5/6 节

**CTA**：在 quickstart 栈执行升级演练，观察回填与回滚断言。

## 文章 3：预置包不是模板——把默认配置、变更预检和质量门禁做成数据

**目标读者**：被“参数太多、每次建库都调一遍”困扰的平台团队。

**标题备选**
- 《零配置但不锁死：把企业默认值做成可版本化的数据件》
- 《配置、预检、评估：让“保存配置”不再等于“重建数据”》

**开篇钩子**
> 零配置最常见的实现是写死一套默认值，然后在客户现场被改得面目全非。
> 我们把默认值做成可校验、可导入、可克隆的预置包，并把“保存”和“重建”拆开。

**结构**
1. 问题：默认值散落在 env、YAML、代码和文档里
2. schema 单一事实源：服务端校验、OpenAPI、前端表单同源
3. 预置包：manifest 声明 retrieval/chunking/impact；建库复制默认值；内置包只读，租户可克隆/编辑
4. 变更预检：`impact` 四类（hot/next_ingest/rebuild/restart），数据契约变更转交迁移
5. 质量门禁：高风险变更保存前需要近期评估；评估回归阈值与告警
6. 边界：当前只有通用企业包；金融/医疗垂直包未交付；权限/合规声明在 B6/B8 前不承诺生效
7. 可复现：`scripts/b23_acceptance.sh`、`scripts/b15c_acceptance.sh`、`/ops/quality`

**证据链接**
- `internal/presets/` 与 `cmd/preset/`
- `migrations/postgres/0034/0035`
- [配置说明](../../configuration.md)
- [发布手册](../../releases.md)

**CTA**：克隆内置包，改 `top_k`，用新包建库观察配置来源。
